# 南宋声景：未经验证的 AI 拟音原型

> **状态：AI 辅助 vibe coding 原型，未经验证。** 本项目的代码、页面、IPA、地域差异、韵脚提示和合成声音，均没有经过历史语言学、方言史、语音学或听辨实验的正式验证。它只能作为可检查的探索工具，**不能**作为南宋临安／金华真实口音、诗词用韵结论或教学／引用依据。

这是一个浏览器内运行的古文朗读实验。用户可粘贴文本，选择“临安行都”或“婺州／金华”，查看逐字音韵信息、押韵提示，并试听／导出确定性的 48 kHz 研究合成 WAV。发布产物是可直接放到 CDN 的静态 SPA：运行时不需要 Node、MLX、Python、模型文件、Worker 或推理服务。

## 当前能做什么

- 用 `tshet-uinh` 查询《广韵》系音韵地位、反切和释义。
- 显示白一平转写、北宋桥接 IPA 和逐层置信等级。
- 以平水 106 韵作格律诗句末的**提示**；不自动裁决换韵、词牌或作品异文。
- 允许对单字读音选择候选项，再导出注释 JSON。
- 在浏览器用规则 DSP 渲染女声风格的研究声音，或用设备自己的中文声线预听。

这不是一个经过验证的“古音 TTS”。48 kHz 只是渲染格式；声音清晰度、自然度和历史可信度是彼此独立的问题。

## 本地启动

需要 Node.js **22.13 或更高版本**。

```bash
npm install
npm run dev
```

打开终端给出的本地地址（通常为 `http://localhost:3000`）。静态发布文件会生成到 `dist/`，将该目录内容上传至支持 SPA 回退到 `index.html` 的 CDN／静态站点即可。运行工程检查：

```bash
npm run test:research
npm run lint
npm run build
```

这些检查只验证数据路径、可重复渲染和前端构建；**不验证拟音或听感是否正确**。

## 系统边界

```text
汉字文本
  → 繁简转换、断句与少量上下文规则
  → 《广韵》系音韵地位
  → 北宋桥接与临安／婺州候选规则
  → IPA、平水韵提示与证据标签
  → 规则 DSP 或设备 TTS
```

每一层都必须单独评价：韵书条目的可靠性，并不会自动证明宋代音值、地方口语或最终合成声音可靠。

| 问题 | 目前状态 | 可行的下一步 |
| --- | --- | --- |
| 《广韵》不等于南宋地方口语 | 字头与音韵地位较可追溯；从切韵系到南宋、临安、金华的映射仍主要是桥接与推断 | 建立“资料—规则—输出”逐条引文表；请历史音韵与浙江方言史研究者逐条审阅；把相互竞争的方案并列展示 |
| 临安／金华差异证据不足 | 当前地域项保守地标为候选，不能据此宣称吴语化细节 | 收集宋人音注、地方文献、韵图、用韵语料及现代方言的可反驳比较；只对有直接证据的音类启用地域规则 |
| 多音、通假、异文与古文分词 | 仅覆盖少量上下文规则，默认候选仍可能错 | 引入带版本的古籍底本、词级读音词典、作者／时代元数据和人工覆写保存；将“无法断定”作为正式输出 |
| 诗词押韵被过度简化 | 平水 106 韵只适合提示一部分格律诗，宋词、古体、通押与 107 韵尚未完成 | 建立作品级“作者—文本—韵段—韵脚”语料；分别编码《礼部韵略》106／107 韵与词牌规则；用校勘本人工回归 |
| 声母仍可能不清晰 | 已加入按部位区分的噪声中心、爆破／塞擦、送气、浊音、鼻音和声母到元音的共振峰过渡；参数尚未做听辨实验 | 制作最小对立对（如 `pa/ta/ka`、`tsa/tʂa/tɕa`）听辨测试；按混淆矩阵调时值、噪声频段和共振峰；将基准音频固定为回归样本 |
| “48 kHz 仍粗糙” | 采样率不是主要瓶颈；规则 DSP 缺少真实声门、声道、协同发音与连续语流模型 | 保留 DSP 作为可控校音器；试验可接受 IPA／音素和时长控制的 WebAssembly 引擎，或用浏览器 ONNX Runtime 加载许可证明确的女声声学模型／声码器 |
| 声音不像真人 | 当前声音是合成器，不是录音，也没有经过自然度评价 | 若目标变为自然女声，建立授权录音语料与目标音素标注，训练／适配 VITS、Piper 等模型；先明确模型、数据和输出的许可证与再分发边界 |
| 听起来对不代表历史上对 | 目前没有专家听辨和文献交叉验证闭环 | 把“文献一致性”“规则一致性”“专家判断”“听辨可懂度”设为独立验收项，公开反例、改动记录和不确定项 |

## 声音改进的取舍

当前 DSP 的目标只是让声母不再全部退化为相似的元音。它为塞音、塞擦音、擦音、鼻音、流音和介音使用不同的起始时值、噪声频段、送气／浊音处理和共振峰过渡；入声塞尾也会朝不同发音部位收束。这些是工程上的可调参数，**不应被误读为南宋声学事实**。

如果未来要追求“清晰且接近真人”的声音，优先顺序建议是：

1. 先做最小对立对听辨与长句可懂度测试，找出真正混淆的声母／韵尾。
2. 保留 IPA、音素时长、入声闭锁和韵脚控制的接口，避免通用 TTS 擅自改写音系。
3. 调研可在浏览器运行的 WASM／ONNX 路线，并验证它是否真的能接受所需音素，而非只会读现代普通话。
4. 只有在授权数据、训练方案、听辨测试和专家审阅都齐备后，才把神经女声作为默认输出。
