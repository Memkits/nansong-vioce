# 南宋声景：未经验证的 AI 拟音原型

> **状态：AI 辅助 vibe coding 原型，未经验证。** 本项目的代码、页面、IPA、地域差异、韵脚提示和合成声音，均没有经过历史语言学、方言史、语音学或听辨实验的正式验证。它只能作为可检查的探索工具，**不能**作为南宋临安／金华真实口音、诗词用韵结论或教学／引用依据。

这是一个浏览器内运行的古文朗读实验。用户可粘贴文本，选择“临安行都”或“婺州／金华”，查看逐字音韵信息、押韵提示，并试听／导出确定性的 48 kHz 研究合成 WAV。发布产物是可直接放到 CDN 的静态 SPA：核心功能不需要 Node、MLX、Python、Worker 或推理服务。可选的“神经代理”会在用户首次启用时从公网下载模型，并在浏览器本地推理。

## 当前能做什么

- 用 `tshet-uinh` 查询《广韵》系音韵地位、反切和释义。
- 显示白一平转写、北宋桥接 IPA 和逐层置信等级。
- 以平水 106 韵作格律诗句末的**提示**；不自动裁决换韵、词牌或作品异文。
- 允许对单字读音选择候选项，再导出注释 JSON。
- 在浏览器用规则 DSP 渲染女声风格的研究声音，或用设备自己的中文声线预听。
- 按需加载 Kokoro 中文女声，作为“接近真人”的现代普通话音质参照；它不读取拟音 IPA，也不是历史拟音。

这不是一个经过验证的“古音 TTS”。48 kHz 只是渲染格式；声音清晰度、自然度和历史可信度是彼此独立的问题。

## 本地启动

需要 Node.js **22.13 或更高版本**。

```bash
npm install
npm run dev
```

打开终端给出的本地地址（通常为 `http://localhost:3000`）。静态发布文件会生成到 `dist/`，将该目录内容上传至支持 SPA 回退到 `index.html` 的 CDN／静态站点即可。运行工程检查：

```bash
npm run test:research
npm run lint
npm run build
```

这些检查只验证数据路径、可重复渲染和前端构建；**不验证拟音或听感是否正确**。

## 系统边界

```text
汉字文本
  → 繁简转换、断句与少量上下文规则
  → 《广韵》系音韵地位
  → 北宋桥接与临安／婺州候选规则
  → IPA、平水韵提示与证据标签
  → IPA 可控规则 DSP／现代普通话神经代理／设备 TTS
```

每一层都必须单独评价：韵书条目的可靠性，并不会自动证明宋代音值、地方口语或最终合成声音可靠。

## 声音改进的取舍

当前 DSP 的目标只是让声母不再全部退化为相似的元音。v3 为塞音、塞擦音、擦音、鼻音、流音和介音使用不同的起始时值、稳定噪声带、送气／浊音处理和共振峰过渡；加入轻微周期扰动、输出滤波，并把普通字间间隔从 24 ms 缩到 12 ms。入声塞尾仍会朝不同发音部位收束。这些是工程上的可调参数，**不应被误读为南宋声学事实**。

如果未来要追求“清晰且接近真人”的声音，优先顺序建议是：

1. 先做最小对立对听辨与长句可懂度测试，找出真正混淆的声母／韵尾。
2. 保留 IPA、音素时长、入声闭锁和韵脚控制的接口，避免通用 TTS 擅自改写音系。
3. 继续调研可在浏览器运行且能接受所需音素的 WASM／ONNX 路线；当前 Kokoro 代理已经证明浏览器神经合成可行，但只会读现代普通话。
4. 只有在授权数据、训练方案、听辨测试和专家审阅都齐备后，才把神经女声作为默认输出。

## 可选神经代理的外部资源

- 模型：`onnx-community/Kokoro-82M-v1.1-zh-ONNX`，Apache-2.0；页面根据能力选用 q4f16／q8，并固定女性声线 `zf_001`。
- 浏览器封装：`@uzen/kokoro-js@1.2.4`，Apache-2.0；从固定版本的 jsDelivr ES module 延迟载入，WebGPU 失败时回退 WASM。
- 模型与声线在 Hugging Face 延迟下载并由浏览器缓存。核心研究合成、音韵分析和静态页面不依赖这些公网资源。
- 没有加入 Piper：当前引擎为 GPL-3.0，公开中文声音的数据许可也需逐个核验；例如 Xiao Ya／BZNSYP 声音注明非商业数据许可，暂不适合作为本项目默认可再分发资源。

外部 URL、版本或托管方失效时，神经代理可能不可用，但不会影响核心静态页面和确定性研究合成。
