# 宋词声景：未经验证的 AI 拟音原型

> **状态：AI 辅助 vibe coding 原型，未经验证。** 本项目的代码、页面、IPA、宋词韵部、临安实现和合成声音，均没有经过历史语言学、方言史、语音学或听辨实验的正式验证。它只能作为可检查的探索工具，**不能**作为宋代文人通语、南宋临安真实口音、宋词用韵结论或教学／引用依据。

这是一个浏览器内运行的宋词与古文朗读实验。默认入口是“宋代文人通语”，其次是尚未完成地域改音的“南宋临安实现”；婺州／金华已降为南部吴语比较资料，不再是主声景。页面按输入、韵脚、逐字拟音、试听的顺序组织。发布产物是可直接放到 CDN 的静态 SPA：核心功能不需要 Node、MLX、Python 或推理服务。Sites 构建中的 Worker 仅转发静态资源与 SPA 回退，不参与分析或合成。可选的“神经代理”会在用户首次启用时从公网下载模型，并在浏览器本地推理。

## 当前能做什么

- 用 `tshet-uinh` 查询《广韵》系音韵地位、反切和释义。
- 显示白一平转写、北宋桥接 IPA 和逐层置信等级；默认通语标 B，临安实验层标 C。
- 先显示韵脚，再显示逐字 IPA；现有平水 106 韵仅作官韵／格律诗**提示**，尚未实现宋词通语韵部。
- 允许对单字读音选择候选项，再导出注释 JSON。
- 在浏览器用规则 DSP 渲染女声风格的研究声音，或用设备自己的中文声线预听。
- 按需加载 Kokoro 中文女声，作为“接近真人”的现代普通话音质参照；它不读取拟音 IPA，也不是历史拟音。
- 新增“音素女声”免训练实验：直接将逐字拟音送入多语种 Kokoro v1.0，生成 24 kHz 女声。声调、入声、罕见音素的声学实现仍未验证，暂不替代默认研究合成。

这不是一个经过验证的“古音 TTS”。48 kHz 只是渲染格式；声音清晰度、自然度和历史可信度是彼此独立的问题。

## 本地启动

需要 Node.js **22.13 或更高版本**。

```bash
npm install
npm run dev
```

打开终端实际打印的 Local 地址（默认请求 `http://127.0.0.1:5173/`，占用时 Vite 会另选端口）。不要沿用其他项目的旧地址；如需固定端口，可执行 `npm run dev -- --port 5175 --strictPort`，端口占用时会明确报错。静态发布文件会生成到 `dist/`，将该目录内容上传至支持 SPA 回退到 `index.html` 的 CDN／静态站点即可。运行工程检查：

```bash
npm run test:research
npm run test:neural-ipa
npm run lint
npm run build
```

这些检查只验证数据路径、可重复渲染和前端构建；**不验证拟音或听感是否正确**。

## 系统边界

```text
汉字文本
  → 繁简转换、断句与少量上下文规则
  → 《广韵》系音韵地位
  → 宋人音注／宋词用韵（待编码）与北宋桥接
  → 宋代文人通语基线
  → 南宋临安接触层（可选、待研究）
  → IPA、官韵参考与证据标签
  → IPA 可控规则 DSP／现代普通话神经代理／设备 TTS
```

每一层都必须单独评价：韵书条目的可靠性，并不会自动证明宋代音值、地方口语或最终合成声音可靠。

## 当前研究主轴

宋词作者来自多地，但现有用韵研究显示江浙词人的主体韵系与中州、山东、江西、福建和四川大体相同，因此产品先建“宋代文人通语”，再标稳定的地域例外。南宋临安是通语之上的城市接触实现，不是另一套凭现代杭州话倒推的完整音表。婺州／金华材料只用于检验南部吴语古层、文白异读和入声演变。资料入口与证据边界见 [DATA_SOURCES.md](DATA_SOURCES.md)。

## 声音改进的取舍

### 为什么现代吴语使用者仍会觉得奇怪（2026-09-06 复查）

用户反馈“音素女声”比之前更像中文，但不同字过于相似、部分字异常。这是有价值的个体听感，不是盲听结论；尚未取得具体听辨字句，不能断定某个音素已经改善。本轮按用户要求提交可审查的实验版本，保留现有波形算法和默认模式，明确列出未修复问题。

**音素女声路径已确认：声调信息未传入声学模型。** `probeReading()` 分离调号并保存在元数据中，但 `createIpaEngine().generate()` 只把无调音素、声线和语速传给模型；没有声调后处理。相／想均成为 `ˈsjɑŋ`，衣／意均成为 `ˈʔi`，古／故均成为 `ˈku`。在相同上下文中，模型没有按原调区分的输入依据；逐字模式同次生成还会命中相同音素／语速缓存。改缓存键或提高 FP32 精度不能恢复未实现的 F0 控制。

新增回归确保原始调类元数据保留，并显式报告上述未修复碰撞，而不将“碰撞必须存在”写成验收要求；同时检查言／元、六／力、先／宣的不同音段仍以不同 token 传入神经模型。这仅证明输入区别未丢失，不证明模型实际发对。后续优先做音节对齐与可控调形、义读选择和实际音段听辨；当前 PR 不是这些问题的修复版。

**另行发现的共享选音／DSP 问题：** 以下问题已在代码／本地波形中复现，但还未修复；此前的正常回归并未覆盖这些缺陷。

- 研究合成 `featureFor()` 只匹配声母前缀，未消费剩余介音和附加符号；韵核只提取元音，韵尾只认 `m/n/ŋ/p/t/k`。因此 `j/ɥ/w`、腭化／咽化等对立可能丢失，`kʲʰ` 还会被前缀 `k` 接走而漏掉送气；`v/ɻ` 没有对应声母参数。未知声母退到无声母、无已知元音退到 `ə` 的静默兜底也须审计。
- 使用实际字音、同为单字索引 0、舒声 630 ms／入声 390 ms、无额外字间隔分别渲染，两波形的归一化内积：言 `ŋjɛ̀n`／元 `ŋɥɛ̀n` 为 **0.999995**；六 `liwk`／力 `lik` 为 **0.999987**。这是合成参数丢失的工程证据，不是听辨准确率；不同随机种子仍使噪声波形略有不同，不能用“哈希不同”判定音素没有合并。
- `readingsFor()` 只有少量上下文特判，其余取数据库首条。“食”首条是人名“郦食其”的 `ǐ`，饮食义另有 `ʐik`；“方”首条是“方与县名”的 `vɑ̀ŋ`，四方义另有 `fɑ̀ŋ`。应按语境／释义选择并公开依据，而不是把现代普通话音值套回去。
- 以上波形测量仅针对 **v7 研究合成**；用户已确认听的是音素女声，不能用 DSP 的介音丢失解释神经模型听感。两条合成路径应分别修复与验收；共享的义读选择问题影响所有入口。现代同音字也可能来自不同历史读音，不能强行合并所有陌生音。

| 层次 | 代码现状／可能原因 | 下一步与验收条件 |
| --- | --- | --- |
| 历史目标 | 仍是北宋 `n_song` 桥接；临安选项没有独立改音规则，不是现代杭州、苏州或上海话 | 将有来源的地域差异单列成可切换比较层，不凭熟悉感修改历史基线或押韵归部 |
| 调域与发声态 | v7 按平上去入选择四套 F0 轮廓；虽有浊声母预发声，但没有清浊相关的阴阳调域和系统发声态模型 | 先从许可明确的单说话人材料测量 F0、声带起振时间和气声指标；区分增加随机噪声与真实气声，不能简单“浊音降调＋加噪” |
| 词组节奏 | DSP 逐字处理；神经实验最多四字只是计算分块，不含词法、句法或变调域 | 先测试明确的双音节词／短语边界，再试可控调形；与逐字基线比较，保持标点静音。不把现代上海变调规则外推成全部吴语或南宋规则 |
| 神经口音 | `af_heart` 是美式英语声线；每字 `ˈ` 提示可能引入不合适的重音节奏，调号分离后未施加 F0 控制。绕过英文 G2P 不等于消除英语声学偏向 | 可先做同一 IPA 的中文声线／去重音小样对照；词表与声线兼容不代表读音准确，通过听辨前不更换默认。若音段失真则停止扩大映射 |
| 入声与音段 | v7 保留 `/p t k/` 闭锁；神经实验不能保证无释放、短时值或清浊／送气对立 | 将音段和韵律分开验收；先测 `/p pʰ b/`、`/t tʰ d/`、`/k kʰ ɡ/`、鼻尾与塞尾，再考虑音段库＋WORLD/PSOLA。后处理改 F0 不能补回模型没发对的辅音 |

研究依据：[Zhang 与 Meng（2012）](https://www.isca-archive.org/tal_2012/zhang12d_tal.html)发现上海吴语双音节变调与句法结构有关；[Xu 等（2022）](https://www.isca-archive.org/speechprosody_2022/xu22_speechprosody.html)在昆山儿童小样本中观察到高低调域的发声态差异；[Chen（2023，预印本）](https://arxiv.org/abs/2307.16199)讨论了分词辅助上海话 TTS 连读变调。三者只支持现代方言比较与实验设计，不提供南宋临安参数。声线语言归属见 [Kokoro 官方声线表](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md)。

成本可控的顺序是：公开且许可合适的参考录音与最小对立样本 → 音段听辨 → 韵律分组 → F0／时长重合成。无需用户提供训练资源，但需要逐项核查网上材料的音频许可，不能把代码许可证当成录音再分发许可。未来报告应固定文本、模式、音量、速度、模型版本和浏览器，分别记录自然度、对立音辨识、韵尾与历史证据；目前没有可据以声称“吴语准确率提升”的测量。

### 免训练音素女声实验（2026-09）

**AI vibe coding／未经验证：这是音质探索，不是已验证的宋音升级。** 在“最后试听方案”中选择“音素女声”，建议先用 `明月，清風。`，再和“研究合成”比较。此实验每次最多 40 个汉字，限制首次等待、内存与推理成本；原有研究模式的输入范围不变。

- 不收集用户录音，不训练／微调，不租 GPU。使用公开的 [Kokoro v1.0 ONNX](https://huggingface.co/onnx-community/Kokoro-82M-v1.0-ONNX) 及 `af_heart` 女声风格，Apache-2.0。模型、词表、声线固定到修订 `1939ad2a8e416c0acfeecc08a694d14ef25f2231`；运行时为锁定的 Transformers.js 3.8.1。
- 选择 v1.0 是因为词表包含 `ɥ`、`ɻ` 等当前拟音需要的记号；**符号存在不能证明模型准确学会了该音**。现代女声风格不能当作古代说话人。
- 路线为 `Reading.ipa → 显式音素转换／词表核对 → ONNX 模型 → 波形`，完全跳过汉字／英文文本 G2P。`ts/dz/tɕ/dʑ → ʦ/ʣ/ʨ/ʥ` 为模型记号转换；`ʐ/ʑ → ʒ` 和省略 `ˤ` 非等价，默认禁止，只能勾选允许近似后启用，每字均可查看。
- 只分离 `n_song` 的三个调号，不把全部组合附加符号一律清空。未知符号、待考字和运行时词表不匹配会阻止生成；不静默吞字，也不偷偷回退成普通话。
- 在浏览器 Web Worker 内运行；默认完整精度 FP32（模型／声线约 327 MB），也可选择 Q8（约 93 MB）。WebGPU 失败时尝试**同精度** WASM，不悄悄降精度。另有本网站的约 22 MB WASM 文件（压缩传输量取决于 CDN）；不上传文本或 IPA。CPU 检查脚本只是开发验证，网页不连接本机服务。
- 用户接受更多计算成本，故将“模型已缓存后约 10 秒内首段出声”作为暂定目标，而非整篇十秒内完成的承诺。首次下载另外提示。首段生成即播放，后续边生成边排队；若推理追不上播放会提示缓冲，完成后的重播／下载不包含计算等待。取消、换模式或改输入会终止旧 worker。
- 默认最多四字连读，不跨标点，减少每字重复起音／收尾和模型开销。可关闭连读作逐字审计。保留原生 24 kHz，仅裁去近数字静音的边缘、轻微淡入淡出及防削波；不上采样冒充音质提升。
- 逐枚标点插入 `630/rate` ms 静音。逐字模式字间额外插入 40 ms；连读模式只在组间加 40 ms，**组内不强行切波形制造逐字空白**。
- **尚未保留的控制：** 平上去的工程调形、630/390 ms 字长、韵脚延长、入声无释放闭锁。本实验采用模型时长；不能因为有 `/p t k/` token 就宣布入声实现正确。显式停顿之外仍可能有模型自带静音。页面已说明这些差异，默认声音模式仍为 v7 研究合成（不是此实验）。

开发者可自行生成真实对照，不需要训练数据：

```bash
# 首次下载固定模型；仅写入被 Git 忽略的 outputs/ipa-smoke/
npm run test:neural-ipa:smoke -- --download
# 后续用已下载资源运行
npm run test:neural-ipa:smoke
# 用 Web WASM 引擎在 Node 内验证 ONNX 运算；不等于浏览器 UI 测试
npm run test:neural-ipa:smoke -- --wasm
# 完整精度的真实 WASM 对照；首次另下载约 326 MB
npm run test:neural-ipa:smoke -- --wasm --fp32 --download
```

输出含 `明月，清風。` 的逐字／连读／DSP 对照 WAV、12 个声母／韵尾探针和测量 JSON，文件名记录后端与精度。对照做 RMS 目标与防削波处理，但没有主观响度等效校准，不能称为严格盲听。自动检查仅验证非静音、有限波形、token 未被删改和不同探针未坍缩成完全相同波形，不证明听辨正确。CI 只执行无需下载模型的映射／停顿／分组回归。

这台 Mac 的单线程 Web WASM 测试中，FP32 单字约 2.7–3.3 秒；另一次四字连读 `明月清風` 从读取本地已下载模型到输出波形约 4.3 秒（含约 0.8 秒初始化）。FP32 进程峰值 RSS 在约 1.3–1.6 GiB 范围；这些是 Node 内 Web WASM 实测，不是浏览器 UI、WebGPU 或所有 Mac 的性能保证。完整精度消除权重量化这一误差来源，**尚未证明听感优于 Q8**。

后续决策：先听辨清浊、送气和韵尾。若罕见音素普遍失真，就停止扩大这条路线，转向许可允许改编再分发的单说话人音段库＋WORLD/PSOLA；若音段足够清楚，再独立测试 F0／时长可控重合成。不要求用户提供录音或训练设备。

### 研究合成 v7 基线

v7 的声调调整参考现代多调方言的声学建模方法：声调辨识不能只靠几条相近直线，还要同时拉开基频音域、运动方向、起止目标和轮廓拐点。苏州／吴江研究显示同一音节内可需要一至三个不同极性、时点和幅度的调形命令；本项目只采用这条可听性原则，没有把其七调／十二调调值映射回南宋。每枚标点的静音按当前语速换算为一个普通舒声音节，连续标点会累计。

当前 DSP 的目标只是让声母不再全部退化为相似的元音。v6 参考经典的声源—滤波器思路，以非对称声门流脉冲激励四级时变共振器；辅音仍用分频噪声、闭塞、爆破、送气和共振峰过渡独立生成。元音与辅音轨分别限幅和校准，避免强爆破把整字元音压成耳语；入声塞尾的共振峰移动也限制幅度并同步衰减，避免闭锁前出现异常尖峰。这是紧凑的工程实现，并非完整复刻 Klatt 合成器，更**不应被误读为南宋声学事实**。

在固定机器上的自动 A/B 中，20 字样本的同步渲染约从 `2.88 s` 降至 `0.28 s`；擦音／塞擦音起始段 RMS 约提高三成，稳态元音相对一阶差分 RMS 从 `0.123` 降至 `0.119`。回归还检查双唇—软腭—齿龈塞音爆破频谱中心依次升高、送气段与不送气闭锁分离、入声末尾保持全零。它们只是可复现的工程代理指标，不等于“人耳必然更清楚”。理论入口为 Klatt 的[串联／并联共振峰合成器论文](https://doi.org/10.1121/1.383940)。

如果未来要追求“清晰且接近真人”的声音，优先顺序建议是：

1. 先做最小对立对听辨与长句可懂度测试，找出真正混淆的声母／韵尾。
2. 保留 IPA、音素时长、入声闭锁和韵脚控制的接口，避免通用 TTS 擅自改写音系。
3. 继续调研可在浏览器运行且能接受所需音素的 WASM／ONNX 路线；当前 Kokoro 代理已经证明浏览器神经合成可行，但只会读现代普通话。
4. 只有在授权数据、训练方案、听辨测试和专家审阅都齐备后，才把神经女声作为默认输出。

## 入声的现代方言对照

v5／v6 没有把现代苏州话或粤语直接当成南宋音值，而只抽取两类可验证的比较线索：现代苏州入声通常较短，并常以喉塞或元音末端喉化实现；粤语入声保留不除阻的 `/p t k/` 韵尾，音节也短于舒声。当前实现保留宋代桥接 IPA 已给出的 `/p t k/` 部位，提前向相应闭锁过渡，末尾 14 ms 完全静音且不添加释放爆破。

可用于下一轮离线测量的公开资源包括：[WenetSpeech-Wu](https://github.com/ASLP-lab/WenetSpeech-Wu-Repo) 及其苏州话 benchmark、[Mozilla Common Voice 粤语](https://commonvoice.mozilla.org/data)、[WenetSpeech-Yue](https://github.com/ASLP-lab/WenetSpeech-Yue)，以及仅 10 分钟但带 48 kHz 女声录音的 [MagicData 苏州话 TTS Lite](https://huggingface.co/datasets/MagicHub/magicdata-dialect-wu-chinese-tts-lite)。最后一项正文许可为 CC BY-NC-ND 4.0，因此本项目不打包、不改编其音频，只把它登记为非商业研究对照。
